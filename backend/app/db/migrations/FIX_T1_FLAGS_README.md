# Исправление проблем с флагами T1

## Найденные проблемы

### 1. Проблема с регистром флагов
**Проблема:** Флаги в базе данных хранились с маленькими буквами в суффиксе (например, `FLAG{IDOR_NEGATIVE_ID_a1b2c3}`), но система валидации в `flags.py` приводит все флаги к верхнему регистру через `.upper()`. Это приводило к несоответствию:
- В базе: `FLAG{IDOR_NEGATIVE_ID_a1b2c3}`
- После `.upper()`: `FLAG{IDOR_NEGATIVE_ID_A1B2C3}`
- Результат: флаг не находился в базе данных

**Решение:** Обновлены все флаги T1 в верхний регистр во всех файлах:
- `backend/app/db/seed.sql`
- `backend/app/db/seed_bugs.sql`
- `backend/app/main.py`
- `backend/labs/ecommerce_return_refund_lab/app/main.py`

**Затронутые флаги:**
- `FLAG{IDOR_NEGATIVE_ID_a1b2c3}` → `FLAG{IDOR_NEGATIVE_ID_A1B2C3}`
- `FLAG{INTEGER_OVERFLOW_d4e5f6}` → `FLAG{INTEGER_OVERFLOW_D4E5F6}`

Остальные флаги T1 уже были в верхнем регистре.

### 2. Система расчета баллов
**Проверка:** Система расчета баллов работает правильно:
- T1 миссии дают **10 баллов** за каждый найденный флаг (согласно спецификации рангов)
- Система использует тир миссии (`mission.tier`), а не поле `points` из таблицы `bugs`
- Поле `points` в таблице `bugs` (50 для T1) не используется для расчета баллов

**Исправление:** В `users.py` эндпоинт `/me/flags` отображал `bugs.points` вместо баллов по тиру миссии. Это исправлено - теперь отображаются правильные баллы по тиру миссии.

**Важно:** Если пользователю начислили больше баллов, чем положено, это могло произойти из-за:
1. Старой версии кода, которая использовала поле `points` из `bugs`
2. Необходимости пересчета баллов для существующих пользователей

## Миграция для существующей базы данных

Для исправления существующей базы данных выполните SQL миграцию:

```sql
-- Исправление регистра флагов T1
UPDATE bugs 
SET flag = UPPER(flag)
WHERE mission_id IN (
    SELECT id FROM missions WHERE tier = 'T1'
)
AND flag != UPPER(flag);
```

Файл миграции: `backend/app/db/migrations/fix_t1_flags_case.sql`
